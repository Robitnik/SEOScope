# task-36 — Site Monitor: інтерфейс (портфельна стрічка, сторінка клієнта, дифи)

- **Пакет:** UI монітора сайтів — портфельна сторінка `#/monitor` зі стрічкою змін, блок на сторінці клієнта, червоний бейдж на картці дашборду, переглядач історії версій і дифів robots.txt / sitemap / сторінок / DNS.
- **Хвиля:** M — спостережуваність сайтів.
- **Depends on:** **35** (двигун і API монітора), адитивно розширює закриті зони task-12 / 18 / 19 / 27 / 28 / 34
- **PLAN.md:** §4.1 (інформаційна архітектура), §4.4 (стани), §12 (`None` ≠ `0`, чесні стани даних)
- **frontend/AGENTS.md:** **обов'язковий і повний** — особливо §3 (anti-slop), §5 (правда даних), §6 (усі стани), §7 (доступність), §11 (адаптив), §14 (копірайт англійською), §15–16 (візуальний цикл і чекліст)
- **AISeoTools:** змін не потребує

---

## Мета (робота оператора, яку закриваємо)

Двигун із task-35 фіксує зміни в БД. Без інтерфейсу вони там і лишаться. Оператор має отримати відповідь на три питання, не відкриваючи консоль:

1. **Чи горить щось просто зараз?** — за 5 секунд, з головного екрана.
2. **Що саме змінилось і коли?** — конкретний URL, конкретне поле, старе значення → нове, точний час.
3. **Що там було раніше?** — уся історія версій із дифом, а не «останній стан».

`alerts-block.js` (task-17) показує просідання/зростання сторінок за даними GSC. Монітор говорить про **зміни стану сайту**, і плутати їх не можна ні в копірайті, ні в CSS-класах.

**Словник цієї таски (англійською, як вимагає AGENTS.md §14):** розділ — **Site Monitor**; запис у стрічці — **change**; рівні — **Critical / Warning / Info**; дія — **Acknowledge**; прогін — **check** (`Full check` / `Hourly check`); ручний запуск — **Check now**.

Прогони монітора не проходять через джоб-двигун (рішення task-35 §3.1), тож `sse.js`/`job-progress.js` до них не застосовні. «Check now» показує прогрес поллінгом рядка прогону раз на 2 с — рівно як `redirect-tool.js` веде свій прогін. Це також означає: **модалка збору не спливає** від фонового моніторингу, що і було метою.

## 2. Обсяг (scope)

**Входить:**

1. Сторінка `#/monitor` — портфельний огляд + стрічка змін по всіх клієнтах.
2. Сторінка `#/client/{id}/monitor` — стан і історія одного клієнта: Robots, Sitemap, DNS & verification, Pages, журнал перевірок.
3. Переглядач версій і дифів (robots.txt, sitemap, сигнали сторінки, DNS-запис).
4. Бейдж відкритих `critical` на картці дашборду й у шапці сторінки клієнта.
5. «Check now» (light / full) з поллінгом і чесним прогресом.
6. Acknowledge зміни з нотаткою; фільтри стрічки; збереження стану у URL.
7. Експорт таблиці сторінок і стрічки змін (кнопки до готових ендпоінтів task-35).
8. Усі стани з AGENTS.md §6 + фікстури для кожного.

**Не входить (свідомо):**

- Редагування налаштувань монітора складнішого за тумблери «Monitoring on/off» і «Monitor while paused» (решта — через `PATCH` з API/CLI).
- Графіки трендів змін у часі. Спочатку потрібна стрічка, що працює; чарти — після реальних даних.
- Канали доставки сповіщень (поза обсягом усієї хвилі, рішення користувача 2026-08-11).

## 3. Рішення

### 3.1 `#/monitor` — портфель

Єдине завдання екрана: **побачити, у кого горить**. Тому порядок зверху вниз:

1. **Смуга стану портфеля** — скільки клієнтів із відкритими `critical`, скільки з `warning`, час останньої перевірки, кнопка `Check all now`. Ніякого героя-банера (AGENTS.md §3).
2. **Відкриті critical** — перше, що видно: рядок = клієнт + тип зміни + суб'єкт (URL/запис) + коли зафіксовано + `Acknowledge`. Червоний **плюс іконка плюс текст рівня** — колір ніколи не єдиний носій сенсу (§7).
3. **Таблиця клієнтів** — назва, час останньої light/full перевірки, лічильники змін за рівнями, стан («OK», «Never checked», «Blocked», «Paused — monitoring off»), посилання на розділ клієнта.
4. **Стрічка змін** усього портфеля з фільтрами `severity`, `type`, `state=open|all`, `client` — стан фільтрів у URL (§12).

`Info` за замовчуванням **згорнутий**: 2 850 сторінок дадуть багато «content changed», і воно не має топити критичне.

### 3.2 `#/client/{id}/monitor` — один клієнт

Чотири блоки, кожен показує **поточний стан + коли востаннє змінювався + вхід в історію**:

- **Robots.txt** — статус, час останньої зміни, ключовий висновок («Googlebot: allowed» / «Site blocked for Googlebot»), список sitemap-директив, кнопка `History` → дифи версій.
- **Sitemap** — кількість файлів і URL, дельта з минулої перевірки (`+3 / −12`), історія. Окремим рядком — **Sitemap health**: `ok / redirects / broken / unavailable` із живого `sitemap_health` (task-35 §3.4.1). Кожне число — посилання у таблицю сторінок із уже застосованим фільтром, щоб від «12 broken» до списку URL був один клік. Якщо спрацював аварійний клапан — чіп `Truncated · N of M checked, rest next run`.
- **DNS & verification** — A/AAAA/NS/MX/TXT, окремим рядком **Google Search Console verification** і **Analytics (GA4 / GTM)**: знайдено/не знайдено/зникло — це те, заради чого замовляли DNS-моніторинг. Історія по кожному запису.
- **Pages** — таблиця: URL, статус, `in sitemap`, indexable, canonical, title, коли востаннє змінювалась, скільки версій. Фільтри: `changed since`, `status`, `not indexable`, **`in sitemap & not 200`**, пошук. Рядок → історія версій сторінки; у кожної версії — посилання «View saved code» на збережений HTML.

Нижче — **журнал перевірок** (kind, час старту, тривалість, перевірено URL, змінено, трафік) і **стрічка змін клієнта**.

У шапці — `Check now` (light | full) і час наступної планової перевірки.

### 3.3 Переглядач дифів

Один спільний компонент на всі чотири типи об'єктів:

- зліва — вибір двох версій із ланцюга (за замовчуванням: остання й попередня), із датою/часом кожної;
- для **сигналів** (сторінка, DNS) — таблиця «поле → було → стало», змінені рядки позначені й текстом, і кольором;
- для **тексту** (robots.txt, видимий текст сторінки) — unified diff, який рахує бекенд (`difflib`); фронт лише розмічає `<ins>`/`<del>` із семантичними тегами, а не самими кольорами;
- посилання «Open saved document» на збережений документ через `/monitor/documents/{sha256}`;
- довгі рядки — власний `overflow-x: auto` контейнер; сторінка ніколи не скролиться горизонтально (§11).

### 3.4 Бейдж на дашборді

`client-card.js` отримує компактний індикатор: `критично N` червоним, інакше — нічого (порожній стан не займає місця). Клік веде на `#/client/{id}/monitor`. Дані беруться **одним** портфельним запитом `GET /monitor/changes?state=open&severity=critical` при завантаженні дашборду, а не запитом на картку.

Порядок сітки не змінюється: task-34 уже опускає паузованих униз, і монітор у це не втручається.

### 3.5 Стани (AGENTS.md §6) — обов'язковий перелік

| Стан | Що показуємо |
|---|---|
| Клієнта ще не перевіряли | «Never checked» + кнопка `Check now`, а не порожня таблиця |
| Перевірка триває | Живий рядок прогону з `Checked N of M`, поллінг 2 с |
| Перший прогін (baseline) | Явна плашка «Baseline recorded — changes will be tracked from the next check» |
| Сайт віддає челендж WAF | «Blocked by site protection» окремо від «Site down» |
| Cap на URL спрацював | Чіп `Truncated · showing first N of M` |
| DNS-резолвери мовчать | «DNS could not be checked» — **не** «записів немає» (`None` ≠ порожньо) |
| Клієнт на паузі | «Monitoring off (client paused)» + тумблер «Monitor anyway» |
| Помилка мережі в UI | Повідомлення + `Retry`, наявні дані лишаються на екрані |

### 3.6 Доступність і копірайт

- Стрічка змін — семантичний список; рівень серйозності озвучується текстом, іконка декоративна (`aria-hidden`).
- Нові критичні події після оновлення сторінки анонсуються в `aria-live="polite"`.
- `Acknowledge` — `<button>` із точним `aria-label` (`Acknowledge: noindex appeared on /pricing`).
- Уся копія — англійська (§14); бренди й ідентифікатори — `translate="no"`.
- Таблиці — справжні `<table>` (це справді табличні дані), із сортуванням через `<th aria-sort>`.

## 5. Тести й перевірка

- **Unit (`tests/unit/frontend/`, за наявним патерном):** форматери рівнів/типів змін, побудова хешів маршрутів, парсинг фільтрів з URL.

Інструмент — Python Playwright у контейнері `api` (пам'ятка: node-харнес у цьому середовищі непридатний, `wait_for_function` блокується CSP — використовувати поллінг).
- **Клавіатура:** повний прохід сторінки монітора без миші, включно з переглядачем дифів.
- **Перевірка на живому: `laxton.se`** має показати червоний `noindex`-запис у стрічці й у блоці Pages — наскрізний сенс усієї хвилі.
