## §0. Досліди на бойових даних (виміряно 2026-09-05, стек піднятий, `localhost:6524`)

### §0.1 ⚠️ Перемикання версій зламане: `ts` втрачає субсекунди, і replay завжди віддає **попередній** знімок

`format_ts` пише 14 цифр (`YYYYMMDDHHMMSS`), а `ArchiveSnapshot.observed_at` зберігає мікросекунди. `resolve_snapshot` шукає `observed_at <= at` — і власний `ts` знімка **ніколи не проходить цю умову**, бо `13:40:46.280052 > 13:40:46.000000`.

Живий доказ на URL із 4 версіями (`https://exxxoticaexpo.com/`, 3XE):

```
ts у /archive/r/<ts>/…            →  який знімок реально віддано (data-snapshot)
20260905085752 (знімок 408c1593)  →  7f434b6f   ← на одну версію старіше
20260904163030 (знімок 7f434b6f)  →  b1bc3eb6   ← на одну версію старіше
20260904134046 (знімок b1bc3eb6)  →  a5a7b47d   ← на одну версію старіше
20260904103104 (знімок a5a7b47d)  →  a5a7b47d   ← «вціліло» лише завдяки фолбеку на найранішу
```

**Чому оператор бачить саме «перемикання не працює», а не «показано не ту дату»:** `shim.js` віддає батьківському чрому `data-snapshot` того знімка, який сервер реально відрезолвив. `archive-viewer.js:onFrameMessage` бачить `data.snapshot !== state.snapshotId` і викликає `adoptFrameSnapshot(<старіший id>)` — тобто **сам відкочує банер, дату, prev/next і адресний рядок назад**. Натиснув Next → фрейм завантажив попередню версію → чром слухняно перемалювався на неї. Візуально нічого не сталося.

Побічний наслідок: одиничні знімки (як `jessica-m-frankel`, `prev=null, next=null`) працюють **випадково** — через фолбек «найраніша версія», а не тому, що резолв правильний.

### §0.2 ⚠️ Скрипти УВІМКНЕНО = гірше, ніж вимкнено. Корінь — `location.href` всередині replay

Скриншоти оператора: без «Disable page scripts» логотип і фото відсутні; з увімкненим чекбоксом (скрипти **вимкнені**) — обидва на місці.

Причина не в шимі й не в lazy-load розмітці, а в тому, **проти якої бази сторінковий JS сам рахує кореневі шляхи**.

Розібрано побайтово на `https://hearwellservices.com/about-us/jessica-m-frankel/`:

1. Картинки заархівовані правильно й у двох копіях розмітки — ліниву (`src="data:image/svg+xml,…"` + `data-lazy-src="/archive/r/…"`) і `<noscript>` із справжнім `src`. **Зі скриптами вимкненими браузер малює `<noscript>`-копію** — звідси «2 виглядає краще».
2. Зі скриптами увімкненими картинки має промоутити WP Rocket LazyLoad. Але тега `<script src=…lazyload…>` у HTML немає — **ні в архіві, ні на живому сайті**. Бібліотеку підвантажує кастомний відкладений лоадер із `custom-css-js/13952.js`:

```js
const load_js = src => $LAB.script(src);            // LAB.js
loadOptimizationScripts = once(async function () {
  load_js('/wp-content/plugins/rocket-lazy-load/assets/js/16.1/lazyload.min.js');
  load_js(`/wp-content/uploads/custom-css-js/13950.js?v=${timestamp}`);
  load_css(`/wp-content/plugins/elementor-pro/assets/css/widget-woocommerce-menu-cart.min.css?v=${timestamp}`);
});
setTimeout(loadOptimizationScripts, 0);             // спрацьовує завжди
```

3. LAB.js нормалізує кореневий шлях **сам**, через `location.href`:
   `C = /^[^?#]*\//.exec(location.href)[0]`, `D = /^\w+:\/\/\/?[^\/]+/.exec(C)[0]`.
   Усередині replay-фрейма `location.href` = `https://seo.theyovth.space/archive/r/<ts>/https://hearwellservices.com/…`, тож `D` = **`https://seo.theyovth.space`**. Далі LAB.js бачить «свій» origin і тягне файл через `XMLHttpRequest`, який наш шим переписує на `/archive/r/<ts>/https://seo.theyovth.space/wp-content/…` — хоста, якого в архіві немає й ніколи не буде.

**Це не гіпотеза — це №1 промах у бойовому `archive_replay_misses`:**

```
11 ×  https://seo.theyovth.space/wp-content/plugins/rocket-lazy-load/assets/js/16.1/lazyload.min.js
 1 ×  https://seo.theyovth.space/wp-content/uploads/custom-css-js/13950.js?v=1788586524450   (×12 різних v=)
```

А сам файл під **правильним** хостом в архіві є і віддається `200`:

```
200  /archive/r/20260904134046/https://hearwellservices.com/wp-content/plugins/rocket-lazy-load/assets/js/16.1/lazyload.min.js
```

Тобто ассет заархівований, але сторінковий JS ніколи не запитує його за тією адресою. Шим патчить `fetch`/`XHR`/`src`/`href`/`setAttribute`, але **не патчить `location`** — а Wayback свій `wombat.js` пише саме заради цього.

Масштаб класу по портфелю: **13 унікальних промахів на власний origin, 23 звернення**.

### §0.3 ⚠️ Артефакти внизу сторінки (скрини 3–5) — це відсутній CSS із cache-buster'ом у query

Той самий лоадер тягне `load_css('/wp-content/plugins/elementor-pro/assets/css/widget-woocommerce-menu-cart.min.css?v=<timestamp>')`. Тут шим спрацьовує **правильно** (`HTMLLinkElement.href` пропатчений, база — `ORIGIN`, тобто справжній хост), і промах виглядає так:

```
1 ×  https://hearwellservices.com/wp-content/plugins/elementor-pro/assets/css/widget-woocommerce-menu-cart.min.css?v=1788586911808
1 ×  …?v=1788586904953   1 × …?v=1788595221721   1 × …?v=1788597779776   (і так далі — 10 різних v=)
```

Два незалежні дефекти під одним симптомом:

- **(a) Ассет ніколи не був заархівований.** `discover_html_assets` — статичний скан HTML/CSS; URL, що існує **лише як рядковий літерал усередині JS**, розвідка не бачить у принципі. Без цього CSS кошик WooCommerce, поле пошуку і Elementor-попап (`POWERPAY LEASING APPLICATION`) рендеряться **нестилізованими й розгорнутими** — рівно те, що на скринах 3–5. Ці ж скрини це підтверджують: артефакти видно **і зі скриптами, і без них**, бо це CSS, а не JS.
- **(b) Ключ не збігся б і якби був.** `normalize_url` тримає query (свідомо — `LAXTON`-сторінки `?taxonomy=…` реальні), тож `?v=<timestamp>` робить кожне завантаження **новим** ключем. По портфелю: **59 унікальних промахів мають query-string** (142 звернення).

### §0.4 ⚠️ Промах у replay віддає **500**, а не 404 — читання пише в SQLite

`_resolve_replay` на кожен промах робить `repo.record_replay_miss(...)` + `session.commit()`. Це **запис у бойову БД на GET-шляху**, з процесу `api`, поки `worker` тримає write-lock (task-62 серіалізував запис лише в межах свого процесу). Живий traceback:

```
sqlalchemy.exc.OperationalError: (sqlite3.OperationalError) database is locked
[SQL: INSERT INTO archive_replay_misses (id, url, url_key, hit_count, first_seen_at, last_seen_at)]
  → HTTP 500
```

Перевірено просто: 4 з 89 статичних посилань сторінки (`gmpg.org/xfn/11`, два `wp-json/oembed`, `maps.app.goo.gl`) віддали `500` замість чесного `404`. 500 від FastAPI йде **без CSP і без `Access-Control-Allow-Origin`** цього модуля, тобто в sandbox-фреймі це жорсткіша помилка, ніж наш власний 404-заглушка.

### §0.5 GET-параметри в адресі в'ювера

Поточний вигляд:


Фронт — статичний mount `RevalidatingStaticFiles(directory=frontend_dir, html=True)` на `/` ([app/main.py:71](../../../app/main.py#L71)), маршрути роутерів включаються **до** нього, тож будь-який шлях `/archive/view/...` можна віддати з бекенда, не чіпаючи mount. Конфліктів немає: у просторі `/archive/` зайняті лише `/archive/r/{ts}/{url:path}` і `/archive/static/shim.js`.

### §0.6 Календар уже написаний — але живе тільки на хабі

## §1. Нова адресація в'ювера (серверний шлях замість GET-параметрів)

### §1.1 Формат

```
/archive/view/snapshot/<snapshot_id>/<ts>/<original url>
```

Приклад:

```
https://seo.theyovth.space/archive/view/snapshot/d2704a11-d5cd-4ef9-8298-48cab43c03dd/20260904134046/https://hearwellservices.com/about-us/jessica-m-frankel/
```

- `ts` — той самий 14-значний UTC-формат, що вже вживає `/archive/r/` (`app/webarchive/replay.py`). Читається як на Wayback.
- URL у хвості приймається **і сирим, і percent-encoded** — рівно як у `/archive/r/{url:path}`. Канонічною (тією, що ставить сам застосунок) робимо **сиру** форму: вона коротша й читабельна, і це вже усталена конвенція модуля.
- `snapshot_id` і `ts` формально надлишкові один щодо одного. Лишаємо обидва свідомо: `snapshot_id` — точна, незамінна адреса версії (після фікса §2 `ts` теж однозначний, але лише в межах секунди), `ts` — людиночитний і дає працездатний фолбек, якщо знімок видалили ретеншном.
- Розбіжність `snapshot_id` ↔ `ts` (наприклад, вручну відредагована адреса) розв'язується **на користь `snapshot_id`**, а адреса тихо канонізується через `history.replaceState`.

### §1.2 Серверна частина — `app/api/archive_view.py` (новий)

Один маршрут, поза `/api/v1` (як і `archive_replay.py`):

```python
@router.get("/archive/view/snapshot/{snapshot_id}/{ts}/{url:path}")
async def archive_view(snapshot_id: str, ts: str, url: str) -> Response
```

Віддає **оболонку** застосунку — `frontend/index.html` як є, з `Cache-Control: no-cache` (той самий контракт, що `RevalidatingStaticFiles` дає для HTML). Це «серверний рендер» у тому обсязі, який тут дійсно потрібен: адреса стає справжнім ресурсом, F5 і прямий вхід за посиланням працюють без hash, а вся розмітка в'ювера лишається там, де вона є.

Свідомо **не** робимо повний SSR банера: чром в'ювера повністю залежить від `GET /api/v1/archive/snapshots/{id}` (prev/next, meta, live-embeds), тобто SSR означав би дублювання того самого DTO у двох рендерерах — саме той клас розсинхрону, який `PLAN §12` називає джерелом брехні в UI. Натомість у `<head>` оболонки додаємо `<link rel="canonical">` і `<title>` з `url` + `ts` (одне звернення до репозиторію), щоб адреса, вкладка браузера і поділена лінка збігалися одразу, без чекання на JS.

Мертве посилання (немає такого `snapshot_id`) → **404 з тією ж оболонкою** і `state-panel state-failed` у ній: чесний стан замість білого екрана (AGENTS §6).

### §1.3 Фронтова частина

- `router.js`: маршрут матчиться **за `location.pathname`**, а не за `location.hash`. `parseRoute()` спочатку перевіряє `ARCHIVE_VIEW_PATH = /^\/archive\/view\/snapshot\/([^/]+)\/(\d{14})\/(.+)$/` і лише потім падає в наявну hash-гілку. Решта застосунку не змінюється жодним рядком.
- Хеш-форма `#/archive/view?snapshot=…` **лишається робочою** і `301`-подібно (через `location.replace`) веде на новий шлях — щоб уже надіслані оператором лінки не вмерли. Це єдина причина, чому старий маршрут не видаляється.
- Переходи (Previous / Next / вибір дати в календарі / перехід по посиланню всередині архівної копії) роблять **`history.pushState` на новий шлях + повний перерендер в'ювера** — «при переходах сторінка оновлюється» з вимоги. `popstate` обробляється тим самим шляхом, тож Back/Forward ходять по версіях, а не викидають зі сторінки. `location.reload()` **не** використовуємо: це вбило б iframe і змусило б браузер качати архівну сторінку заново на кожен клік.
- `replaceArchiveViewHash()` → `replaceArchiveViewPath()`; `buildArchiveViewHash()` → `buildArchiveViewPath()`. Викликів двоє (`archive-page.js`, `archive-viewer.js`) — обидва у власності цієї таски або сусідні адитивні.

> **Розбіжність із дослівним формулюванням вимоги.** У запиті шлях був `…/snapshot/<id>/<ts>/<percent-encoded url>`. Беремо сирий URL (percent-encoded теж приймається) — щоб адреса в'ювера і адреса replay (`/archive/r/<ts>/<url>`) виглядали однаково; інакше в одному продукті співіснували б дві несумісні конвенції для тієї самої сутності.

## §2. Фікс перемикання версій (корінь §0.1)

### §2.1 `resolve_snapshot` — порівняння з точністю до секунди

`ts` — це **секунда**, а не мить. Отже і порівняння має бути секундним:

```python
upper = at + timedelta(seconds=1)
stmt = select(ArchiveSnapshot).where(
    ArchiveSnapshot.archive_url_id == archive_url_id,
    ArchiveSnapshot.observed_at < upper,           # було: observed_at <= at
).order_by(ArchiveSnapshot.observed_at.desc()).limit(1)
```

Семантика «остання версія, що була живою на момент `ts`» зберігається; змінюється лише те, що знімок, зроблений **у цю саму секунду**, тепер вважається живим у цю секунду. Два знімки однієї сторінки в межах однієї секунди неможливі за конструкцією капчуру (медіана 5.8 с/URL, task-62 §0), тож неоднозначності не виникає.

Те саме — в `resolve_asset_version` (та сама формула, той самий `ts`, той самий баг: версія ассета, оновлена в межах секунди від знімка, зараз резолвиться на попередню).

**Фолбек «найраніша версія» лишається як є** — він потрібен для звернення до моменту, коли URL ще не існував, і після цього фікса перестає маскувати off-by-one.

### §2.2 Чром більше не дає фрейму себе переставити «назад»

Навіть із правильним резолвом `adoptFrameSnapshot` лишається шляхом, яким фрейм може перемістити чром. Додаємо єдину умову: чром приймає `data.snapshot` від шима, **тільки якщо змінився і `data.url`** (тобто це реально перехід на іншу сторінку за посиланням), а не коли фрейм просто перезавантажив ту саму адресу. Інакше — ігнор із записом у `console.debug`. Це страхує від будь-якого майбутнього розсинхрону резолву, а не лише від цього.

### §2.3 Що це дає одразу

Після §2.1 адреса `/archive/r/<ts>/<url>` уперше стає **точною**: кожна з 4 версій `exxxoticaexpo.com` віддає саме себе. Перевірка — в §6.

## §3. Вірність replay зі скриптами (корінь §0.2–§0.4)

Чотири незалежні зміни, від найдешевшої до найдорожчої. Кожна цінна сама по собі.

### §3.1 `shim.js`: власний origin ≠ архівний origin (закриває §0.2)

`toReplayUrl` отримує ще одну гілку **перед** побудовою replay-адреси:

```js
// Сторінковий JS, що рахує кореневий шлях від location.href (LAB.js, будь-який
// власний лоадер), отримує НАШ origin і будує "https://seo.theyovth.space/wp-content/…".
// Такого хоста в архіві немає й не буде — це завжди помилка адресації, ніколи
// не легітимне посилання, бо все наше живе під /archive/.
if (absolute.indexOf(SELF_ORIGIN) === 0) {
  var rest = absolute.slice(SELF_ORIGIN.length);
  if (rest.indexOf("/archive/") === 0) return value;   // уже наше — не чіпати
  absolute = new URL(rest, ORIGIN).href;               // перевісити на архівний хост
}
```

`SELF_ORIGIN` передається тим самим `data-`-атрибутом, що вже несуть `data-ts` / `data-origin` / `data-snapshot` — сервер знає його з `request.url`, шим не має його вгадувати.

Це наш мінімальний, точковий аналог `wombat.js`-івського перехоплення `location`. Повний проксі `window.location` **свідомо не робимо**: він недосяжний без `allow-same-origin`, а послаблювати sandbox заради цього — обміняти реальну безпекову гарантію (task-59 §1.6) на зручність.

Очікуваний ефект, вимірюваний: промах `seo.theyovth.space/wp-content/plugins/rocket-lazy-load/…` (11 звернень, №1 у таблиці) зникає; `lazyload.min.js` вантажиться з архіву; `data-lazy-src` промоутиться; логотип і фото з'являються **зі скриптами увімкненими**.

### §3.2 Резолв ассета з фолбеком по cache-buster'у (закриває §0.3b)

У `_resolve_replay`, **лише для гілки ассета** (не для сторінки — там query значуща, `LAXTON`):

1. точний ключ (як зараз);
2. якщо промах і в URL є query — ключ **без query** (`normalize_url(url, keep_query=False)`, прапорець уже існує саме для цього випадку);
3. якщо і це промах — ключ по префіксу `host/path?%` з `LIMIT 1`, `ORDER BY` за найновішою версією (індекс по `url_key` вживається як prefix-scan).

Крок 3 закриває симетричний випадок: у архіві лежить `…menu-cart.min.css?v=1788000000000`, а сторінка просить `?v=1788604050059`.

**Чому це не порушує правдивість архіву:** віддається байт-у-байт **збережений** ассет того ж шляху, ніколи не мережа. Найгірший наслідок — оператор бачить стилі з іншої ревізії того самого файлу, і цей факт **видно**: кожне таке влучення пишеться в `archive_replay_misses` з позначкою `resolved_by="query_fallback"` і показується в Meta-панелі (§3.5).

### §3.3 Розвідка URL усередині JS (закриває §0.3a)

`app/webarchive/assets.py` отримує `discover_js_string_assets(js_text, base_url)`:

- шукає рядкові літерали (`'…'`, `"…"`, `` `…` ``), що виглядають як шлях або абсолютний URL **того самого хоста**;
- **обов'язково** закінчуються (до `?`) на розширення з жорсткого allowlist: `.js .css .woff .woff2 .ttf .otf .eot .svg .png .jpg .jpeg .webp .avif .gif .ico .mp4 .webm .json`;
- відкидає літерали з інтерполяцією всередині шляху (` `${x}/a.js` `) — адресу відновити неможливо, а вгадувати архів не має права; такі пишуться в лог капчуру як `js_asset_unresolvable`, щоб діра була **видимою**, а не тихою;
- шаблонний літерал із інтерполяцією **тільки в query** (` `/a/b.js?v=${t}` `) приймається зі **зрізаним** query — це рівно кейс `13950.js?v=${timestamp}`, і §3.2 його потім резолвить;
- застосовується до тіл інлайнових `<script>` **і** до вже завантажених JS-ассетів (той самий один рівень розгортання, що task-60 зробив для CSS — не рекурсія);
- обмежене окремим бюджетом `archive_js_discovered_assets_per_page` (дефолт 20), щоб мініфікований бандл не роздув чергу.

Евристика — і план це визнає прямо. Тому вона (а) обмежена allowlist'ом розширень і бюджетом, (б) вимірюється: у Completion report має бути число «скільки нових ассетів знайдено по портфелю і скільки з них віддали 200».

### §3.4 Промах ніколи не валить відповідь (закриває §0.4)

`record_replay_miss` на read-шляху загортається так, щоб **жодна помилка БД не змінювала відповідь**:

```python
try:
    repo.record_replay_miss(original_url, key)
    session.commit()
except OperationalError:                 # database is locked — писати нікуди, але це не привід ламати replay
    session.rollback()
    logger.warning("archive_replay_miss_unlogged url=%s", key)
```

Плюс тонший фікс: журнал промахів — це телеметрія, а не дані архіву, тож він **не має права** тримати транзакцію на GET. Пишемо його через невеликий буфер у пам'яті процесу з періодичним flush (той самий підхід «прогрес як дані, запис серіалізовано», що task-62 узаконив `ArchiveWriteController`), а не по одному INSERT на кожен підресурс сторінки.

### §3.5 Промахи стають видимими в Meta-панелі

Зараз панель показує `Assets: 25 captured, 0 missing` — і це формально правда (`assets_missing` рахує лише **прилінковані** ассети без версії), але оператор із цього робить хибний висновок «усе на місці», тоді як сторінка тихо не догрузила три файли. Додаємо окремий рядок:

```
Replay misses   3  (2 resolved from another revision, 1 not archived)
```

із джерелом `archive_replay_misses` за хостом цього знімка. `PLAN §12`: відсутнє ≠ нуль, і UI мусить розрізняти «нічого не бракує» і «ми не рахували».

## §6. Definition of Done / Gate

1. **Адреса.** `/archive/view/snapshot/<id>/<ts>/<url>` відкривається прямим вводом і F5. Старий `#/archive/view?snapshot=…` веде на неї. Previous/Next/календар змінюють адресу і перемальовують сторінку; Back/Forward ходять по версіях.
2. **Версії.** На `https://exxxoticaexpo.com/` (4 версії) кожен із 4 `ts` віддає **свій** знімок — перевірка тим самим однорядковим циклом із §0.1, всі 4 рядки збігаються. Банер після Next не відкочується назад.
3. **Скрипти.** На `hearwellservices.com/about-us/jessica-m-frankel/` **зі скриптами увімкненими** видно логотип у шапці, фото Jessica M. Frankel і бейдж American Board of Audiology. Промах `seo.theyovth.space/wp-content/…lazyload.min.js` більше не з'являється в `archive_replay_misses` після нового перегляду.
4. **Артефакти.** Низ сторінки (футер, кошик, пошук, попап PowerPay) відрендерений стилізовано; `widget-woocommerce-menu-cart.min.css` резолвиться (через §3.2 або §3.3 — у звіті вказати, через що саме).
5. **Помилки.** Жоден промах не віддає `500`: `gmpg.org/xfn/11`, обидва `wp-json/oembed`, `maps.app.goo.gl` віддають `404` з нашим CSP і `Access-Control-Allow-Origin`.
6. **Календар.** У банері є кнопка з датою; поповер показує ті самі дні й версії, що хаб; клавіатура і `Escape` працюють.
7. **Тести.** `docker compose exec api poetry run pytest tests/unit/webarchive tests/unit/api/test_archive_api.py tests/unit/api/test_archive_replay_api.py -q` — зелено. `ruff check .` + `mypy app` — зелено.
8. **Візуальний loop** (AGENTS §15–16): скриншоти в'ювера 1440 і 390 зі скриптами on/off, до і після, у `tests/e2e/frontend/screenshots/`.
9. **Виміряно і записано в Completion report:** скільки унікальних промахів було до (115 / 408 звернень) і після; скільки нових ассетів дала §3.3 і який відсоток із них віддав `200`.
