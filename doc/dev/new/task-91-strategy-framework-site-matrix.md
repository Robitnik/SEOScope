## Мета (робота оператора, яку закриваємо)

Сьогодні звіт пакета показує **перелік порушень**. Оператор натомість працює
іншою одиницею: «ось сторінка — що по ній сказала стратегія, що написав
копірайтер у фреймворку, що реально стоїть на сайті, і де вони розійшлися».
Перелік findings відповідає на «що не так», але не показує **три значення
поруч**, а саме їх зіставлення і є ручною роботою, яку тул має зняти.

Форма, замовлена користувачем — чотири горизонтальні блоки з однаковими
шістьма колонками, рядки вирівняні за сторінкою:

```
                              СТРАТЕГІЯ
URL | Title | Description | H1 | Ключі | Вихідні посилання
--------------------------------- дані ---------------------------------
                              ФРЕЙМВОРК
URL | Title | Description | H1 | Ключі | Вихідні посилання
--------------------------------- дані ---------------------------------
                                 САЙТ
URL | Title | Description | H1 | Ключі | Вихідні посилання
--------------------------------- дані ---------------------------------
                               ВЕРДИКТ
URL | Title | Description | H1 | Ключі | Вихідні посилання
------------------------------- галочки --------------------------------
```

Плюс експорт цієї ж матриці в Excel — бо саме її пересилають клієнту й
редактору, а не посилання на внутрішній дашборд.

## 1. Дослідження (заміряно живо 2026-09-09, не з документації)

### 1.1 Модель уже має всі шість полів — нових сутностей не треба

`ContentItem` (`app/contentqa/model.py`) несе `url`, `title`, `description`,
`h1`, `keywords`, `internal_links`, `external_links`. Обидва читачі —
табличний (`readers/tabular.py:_ALIASES`) і документний
(`readers/gdoc.py:_LABELS`) — ці поля вже заповнюють. **Матриця не потребує
нового парсингу стратегії чи фреймворку**, лише зведення й порівняння.

### 1.2 Заповненість полів по портфелю (12 живих стратегій)

| Поле | У скількох стратегіях присутнє | Коментар |
|---|---|---|
| `title` | **12/12** | завжди |
| `description` | **12/12** | завжди |
| `keywords` | **12/12** | але подекуди 1 значення на 518 рядків (3XE) |
| `url` | **11/12** | **виняток — SHB, колонки URL немає взагалі** |
| `h1` | 8/12 | |
| `internal_links` | 8/12 | |
| `external_links` | **2/12** | рідкість, не norm |

Наслідок для дизайну: клітинка матриці має **три стани, не два** —
значення / «поле є, але порожнє» / «колонки в джерелі немає». Це той самий
інваріант PLAN §12, на якому вже стоїть увесь Content QA (`None` ≠ `""`).
Половина колонок блоку «Стратегія» на реальних файлах буде саме третім
станом, і показати його як порожню клітинку означало б збрехати.

### 1.3 Сайт: чотири поля з шести є, **вихідних посилань немає взагалі**

`LivePage` (`app/contentqa/site.py`) + `PageSignals`
(`app/monitor/page.py`) дають `url`, `title`, `description`, `h1`,
заголовки H2-H4, `word_count`. **`<a href>` не парситься ніде** — це та сама
дірка, що task-90 §10 лишив як follow-up `site-internal-link-missing`.
Колонка «Вихідні посилання» блоку «Сайт» без цього фізично не існує → це
**перший обов'язковий крок реалізації**, не опція.

«Ключів» на сторінці як поля не існує в принципі: у блоці «Сайт» колонка
«Ключі» означає **скільки із заявлених ключів реально знайдено** в
title/H1/тексті (`PageSignals.visible_text` уже є).

### 1.4 Формати посилань у трьох джерелах — РІЗНІ (головна складність)

Заміряно на живих файлах:

| Джерело | Приклад значення |
|---|---|
| Стратегія (`SDS_SEO_STRATEGY_032026`) | `INT LINK 1 - https://www.shorelinedentalstudio.com/services/invisalign/` |
| Фреймворк (`SHB_FRAMEWORK_MENU_PAGE_082726`) | `Smash House menu → /menu/` |
| Сайт | — (не витягується) |

Тобто: мітка-префікс + **абсолютний** URL проти анкор + стрілка +
**відносний** шлях. Пряме порівняння рядків дало б 100% хибних розбіжностей.
Потрібен спільний нормалізатор → канонічний ключ через наявний
`inspector_key()` (`app/urlinspector/urlkey.py`), який уже вирішує проблему
trailing slash (памʼятка: `per-url-data-join-gotchas` — слеш губить 96%
матчів).

### 1.4a Поправка (заміряно ще живіше, після §1.4): формат Framework-посилань — не один, а п'ять

§1.4 показав лише SHB (`анкор → /шлях`) і зробив висновок «різні формати —
дві мітки». Ширший живий зріз (по одному Framework-документу з 6 різних
клієнтів) показав, що сам arrow-формат — **не конвенція коду**
(`readers/gdoc.py:_link_lines` віддає рядок як є, без жодного парсингу) —
а **звичка конкретного копірайтера**, і вона різна по клієнтах:

| Клієнт | Реальний рядок `internal_links` |
|---|---|
| SDS/SAPHNY | `Dental Implants (/services/tooth-replacement/dental-implants/) - in "Discuss Implant Support"` — шлях **у дужках** |
| 3XE | `2026 EXXXOTICA locations → /locations/` — arrow-формат (єдиний, що збігається з §1.4) |
| LAXTON | `utrustning för spökjakt → placement: H2 "Utrustningen bakom undersökningarna"` — **arrow є, але після нього НЕ шлях**, а опис місця вставки |
| PJC / EFFYS | `make a reservation`, `Effy's UWS location` — **шляху нема взагалі**, це проза для людини-копірайтера |

Наслідок для §2.3/матриці: наївний "усе після →" зламався б на LAXTON.
Екстрактор (§2.2 нижче) мусить бути **захисним із багатьма спробами**, а не
одним патерном: (1) абсолютний `https?://…`, (2) шлях у дужках `(/…)`,
(3) шлях одразу після `→`, і лише тоді, коли те, що після стрілки,
**починається з `/`** (рятує від LAXTON), інакше — (4) *не* екстраговано.
Стан (4) — це не помилка й не привід крашити: чинний дизайн §2.3 вже описує
`not_comparable`, коли менше двох джерел мають значення, тобто цей випадок
уже покритий архітектурою, лише сам екстрактор мусить чесно визнати
поразку, а не вигадати URL звідкись.

### 1.5 Ключі нормалізовані по-різному в стратегії й фреймворку

Той самий рядок SHB, `Our Story`:

- стратегія: `('smash house kosher', 'smash house burgers\nsmash house burger\nsmash house burger kosher', 'is smash house kosher')` — **три ключі склеєні переносами в один елемент**;
- фреймворк: `('smash house kosher', 'smash house burgers', 'smash house burger', 'smash house burger kosher', 'is smash house kosher')` — розбиті.

Множини **однакові за змістом**, але не за структурою. Порівняння без
спільної нормалізації (`splitlines` + trim + casefold + dedupe) дало б
розбіжність там, де її немає.

### 1.6 Регістр: жива пастка на H1

`/menu/`: фреймворк каже `Our Smashed Burgers Menu`, сайт віддає
`OUR SMASHED BURGERS MENU`. Для SEO це **не** розбіжність. Порівняння всіх
текстових полів — casefold + згортання пробілів; сам показ у таблиці —
як є, без нормалізації (оператор має бачити фактичний текст).

### 1.7 Реальні розбіжності, які матриця покаже одразу

На тому ж SHB (три рядки, живий прогін):

- `/our-story/`: стратегія і фреймворк — `Smash House | Our Story & Kosher Burger History`, сайт — `Our Smash Burger History | Smash House`. **Title розійшовся**, і description теж.
- `/menu/`: title у фреймворку `Smash Burger Menu | Burgers, Chicken & Dirty Fries`, на сайті `Smash House Burger Menu: Burgers, Fries & More`. **Розбіжність.**
- H1 на обох збігається (з точністю до регістру).

Тобто матриця має що показувати з першого ж прогону — вона не буде
«зеленою стіною».

### 1.8 Excel: патерн у проєкті вже усталений (8 місць)

`app/pageinventory/xlsx.py`, `app/reports/{xlsx,monthly_xlsx,batch_xlsx}.py`,
`app/api/tools_alt_text.py` та ін. Конвенція, сформульована в докстрінгу
`pageinventory/xlsx.py` і обовʼязкова тут: **білдер приймає той самий
DTO-список, що читає JSON API і екран — ніколи другу, незалежно виведену
копію даних.** Підпис: `build_*_xlsx(rows) -> bytes`, віддача —
`StreamingResponse` з `media_type=…spreadsheetml.sheet`.

### 1.9 Чого немає в БД

`content_qa_packages` (task-90) зберігає findings, стани звірок і стани
аркушів — але **не самі значення полів**. Відкритий старий звіт побудувати
матрицю не зможе. Отже потрібна нова колонка (`matrix_json`) + міграція;
без неї експорт працював би тільки одразу після прогону.

## 2. Рішення (архітектура)

### 2.1 Рядок матриці = сторінка, не документ

Ключ рядка — `inspector_key(url)`, коли URL відомий хоч в одному джерелі;
інакше — рядок стратегії (`strategy_ref`, точний `Sheet!row N`, механізм
`known_row` уже є з task-90 §4.5, бо SHB не має колонки URL, §1.2).

У матрицю потрапляють **усі три види рядків**, кожен зі своїм чесним станом:

1. стратегія + фреймворк + сайт — повний рядок;
2. рядок стратегії **без** фреймворку (на SHB таких 39) — блок «Фреймворк» = «немає»;
3. фреймворк **без** рядка в стратегії — блок «Стратегія» = «немає».

Так два наявні агрегатні findings (`sync-strategy-row-no-frame` і
«не знайдено в стратегії») стають видимими структурно, а не текстом.

### 2.2 Новий модуль `app/contentqa/matrix.py` — чиста функція

```python
build_matrix(strategy: ContentDoc, outcomes: list[FrameworkOutcome]) -> list[MatrixRow]
```

Без HTTP, без БД, без FastAPI — той самий принцип, що `run_package`
(task-90 §2.6). `MatrixRow` тримає по три `CellValue` на кожне з шести полів
плюс вердикт:

```python
CellState = Literal["value", "empty", "absent"]   # значення / порожньо / поля немає

@dataclass(frozen=True)
class Cell:
    state: CellState
    text: str | None            # як у джерелі, без нормалізації — для показу
    items: tuple[str, ...] = () # для ключів і посилань

Verdict = Literal["match", "mismatch", "not_comparable"]
```

`not_comparable` — окремий третій стан (сторінка недоступна, поля немає,
порівнювати нема з чим). Ніколи не «match» за замовчуванням.

### 2.3 Порівняння — по одному нормалізатору на тип поля

| Поле | Правило вердикту |
|---|---|
| URL | `inspector_key()` збігається між усіма наявними; редірект сайту на інший URL = `mismatch` |
| Title / Description / H1 | casefold + згортання пробілів (§1.6) |
| Ключі | множини після `splitlines`+trim+casefold+dedupe (§1.5); сайт — скільки заявлених знайдено у visible_text |
| Вихідні посилання | множини канонічних ключів (§1.4); сайт — чи заявлені посилання реально стоять на сторінці |

Джерел може бути два, а не три (немає фреймворку / сайт недоступний) —
вердикт тоді рахується по наявних, а не оголошується `not_comparable`
автоматично; `not_comparable` лише коли **менше двох** джерел мають значення.

### 2.4 Витяг посилань із сайту (`site.py`, адитивно)

`_HeadingParser` уже ходить по HTML і вміє пропускати `nav`/`footer`
(task-90 §4.4) — той самий обхід збирає `<a href>`. Свідомо: посилання з
навігації/підвалу **не** рахуються вихідними посиланнями сторінки, інакше
кожна сторінка «має» все меню сайту. Розділення internal/external — за
хостом канонічного URL.

### 2.5 Матриця не замінює findings, а стає головним поданням

Вкладка «Comparison» стає першою й відкритою за замовчуванням; наявні
Strategy / Frameworks / Cross-checks лишаються поруч. Причина: матриця
показує **шість полів**, а рушій перевіряє їх десятками правил (slop, voice,
readability, довжини, канібалізація) — викинути findings означало б
викинути те, чого матриця структурно не вміє показати. Рішення дешево
відкотити: якщо оператору вкладки заважають, прибирається один масив.

## 3. Етапи

**3.1 Посилання з живої сторінки** (`site.py`) — `<a href>` у `LivePage`,
абсолютизація відносних, розділення internal/external, пропуск nav/footer.
Юніт-тести + живий замір на 3 сторінках SHB.

**3.2 Нормалізатори** (`matrix.py`) — ключі (§1.5), посилання (§1.4),
текст (§1.6). Кожен закритий тестом на **живо заміряних** значеннях із §1.4-1.6,
не на вигаданих.

**3.3 `build_matrix()`** — зведення трьох джерел, три види рядків (§2.1),
вердикти (§2.3). Чиста функція, тести без мережі.

**3.4 БД + API** — колонка `matrix_json` (`op.add_column`, **без**
`batch_alter_table`, CLAUDE.md), `pg_dump -Fc` **перед** міграцією;
`MatrixRowDTO` у схемах; `/check` наповнює, `/reports/{id}` віддає.

**3.5 Excel** — `app/contentqa/matrix_xlsx.py` за конвенцією §1.8: чотири
блоки на одному аркуші (як на екрані) + окремий аркуш `Mismatches` лише з
розбіжностями. `GET /reports/{id}/matrix.xlsx`, реєстрація в
`app/audit/actions.py`.

**3.6 Фронт** — вкладка «Comparison» з чотирма блоками, кнопка «Export to
Excel», фільтр «лише розбіжності». Горизонтальне прокручування — всередині
контейнера з `contain: paint` (памʼятка `table-scroll-contain-paint`: без
нього широка таблиця тягне за собою всю сторінку), ланцюжок `?v=` збамплений
до `index.html`.

**3.7 Жива перевірка** — SHB (title-розбіжності §1.7 мають зʼявитися),
SDS (абсолютні посилання + колонка URL є), ALPHA (нуль посилань),
недоступна сторінка → `not_comparable`, а не «match».

## 4. Ризики й пастки

| Ризик | Мітигація |
|---|---|
| Порожня клітинка читається як «збігається» | Три стани клітинки (§1.2) і три стани вердикту (§2.2); `absent` рендериться візуально інакше, ніж `empty` |
| Хибні розбіжності на форматах посилань/ключів/регістру | Нормалізатори §2.3, кожен на заміряних значеннях (§1.4-1.6) — це вже спіймано до реалізації, не після |
| 6 колонок × довгий description не влазять | Скрол усередині контейнера + `contain: paint`; клітинка з обрізанням і повним текстом у `title`/розгортанні |
| Матриця будується з другої копії даних | Заборонено §1.8: Excel і екран читають **той самий** `MatrixRowDTO` |
| Старі звіти без `matrix_json` | Nullable колонка + чесний порожній стан «this report predates the comparison table», не краш |
| Міграція на бойовій БД | `pg_dump -Fc` перед, `op.add_column` без `batch_alter_table` |
| Сайт-посилання роздують payload | Зберігати канонічні ключі, не сирі href; cap на кількість у клітинці з лічильником «+N» |

## 5. Definition of Done

1. Усі шість полів × три джерела зведені в матрицю; **три стани клітинки** розрізняються візуально.
2. Вердикт має три стани; недоступна сторінка дає `not_comparable`, ніколи «match».
3. Нормалізатори закриті тестами на живо заміряних значеннях §1.4-1.6 (склеєні ключі, `INT LINK 1 - …`, `анкор → /шлях`, CAPS-H1).
4. На SHB живо відтворені розбіжності title/description із §1.7; збіг H1 не позначений як розбіжність.
5. Рядки стратегії без фреймворку і фреймворки без рядка стратегії присутні в таблиці.
6. Excel відкривається в LibreOffice/Excel; числа й переноси не поламані; аркуш `Mismatches` містить рівно ті рядки, що позначені ✗.
7. Excel і екран побудовані з одного DTO (перевірка: підміна одного значення в API змінює обидва).
8. `ruff check .`, `mypy app`, `pytest tests/unit/contentqa tests/unit/api` — зелені в Docker.
9. Бекап `pg_dump -Fc` зроблений до міграції, файл названий у Completion report.
10. Фронт: візуальний loop 1440/390, нуль емодзі, нуль inline-стилів, `?v=` збамплений; сторінка не скролиться горизонтально через таблицю.
11. Новий ендпоінт експорту зареєстрований у `app/audit/actions.py`.
