## **РОЗБІЖНІСТЬ**

Продукт (обидва режими — `source=api` і `source=pdf`) **точно збігається з арбітром на всіх
чотирьох метриках**. Розбіжність існує **поза продуктом**: у допоміжному CLI-скрипті AISeoTools
(`client-report`, джерело №5) і у власному підсумковому віджеті Reporting Ninja (джерело №4, PDF).
Обидві розбіжності мають конкретну, перевірену причину — різна модель атрибуції GA4 — і жодна з них
не є дефектом інструмента, який показуємо клієнту. Деталі — §Розбіжності нижче.

За правилом §4.5/G8 плану: наявність хоч одного розбіжного рядка означає, що вердикт **не** може
бути `МАТЧ`, навіть коли причина зрозуміла й не в продукті.

## §3. Розбіжності (§4.2 плану) — абсолютне й відносне відхилення від арбітра

| Джерело | Метрика | Значення | Арбітр | Δ абс. | Δ % | Допуск (§5) | Статус |
|---|---|---|---|---|---|---|---|
| RN API (AISeoTools `client-report`) | organic_users | 6,510 | 6,828 | −318 | −4.66% | ≤1% | ❌ поза допуском |
| RN API (AISeoTools `client-report`) | organic_conversions | 1,115 | 1,178 | −63 | −5.35% | 0 | ❌ поза допуском |
| RN PDF, підсумковий віджет "Organic Conversions" | organic_conversions | 1,255 | 1,178 | +77 | +6.54% | 0 | ❌ поза допуском (для порівняння: та сама сторінка PDF у таблиці по каналах показує коректні 1,178 — це внутрішня неузгодженість самого PDF, не наша) |

Усе інше (clicks, impressions на всіх 7 машинних+UI джерелах; organic_users/organic_conversions на
GA4 UI, Google API напряму, RN PDF-таблиці, обох режимах нашого тула, БД) — **точний нуль
відхилення**.

### Гіпотези причин (перевірені, не здогад — §6.2 плану)

**RN API (AISeoTools `client-report`) — джерело №5.**
Перевірено код: `seo_audit/clientreport/ga4_fetcher.py` в AISeoTools (сусідній репозиторій,
`/home/elon/dev/seo/AISeoTools`, поза Owned paths цієї задачі — лише прочитано)
запитує РІВНО поле `sessionMedium` (сирий UTM-медіум, атрибуція за сесією), а не
`firstUserDefaultChannelGroup` (атрибуція за першим користувачем), який використовують **усі** інші
джерела — включно з нашим продуктом (`app/reports/google_source.py`, `app/reports/api_source.py`).
Це гіпотеза **§6.2.3 плану** ("Модель атрибуції GA4… вже давало 5–15% розходження"), підтверджена
прямим читанням коду, а не здогадом. Причина не в продукті: `client-report` — окремий,
допоміжний CLI-скрипт AISeoTools для швидкого разового звіту, інша кодова база, інша модель за
задумом його автора, не помилка.

**RN PDF, підсумковий віджет "Organic Conversions" = 1,255 — джерело №4.**
На тій самій сторінці PDF є ДВІ таблиці по каналах: одна підписана як "First user default channel
grouping" (насправді дані first-user — Key events для Organic Search = 1,178, збігається з арбітром),
і друга — з тим самим заголовком, але фактично колонка `Session primary channel group` (сесійна
атрибуція — Organic Search Key events = 1,122). Підсумковий віджет угорі PDF (1,255) — це сума
СЕСІЙНОЇ таблиці: `Organic Search (1,122) + Organic Social (133) = 1,255`. Тобто віджет комбінує
ОБИДВА чинники з §6.2 одразу: інша модель атрибуції (сесія, не перший користувач) **і** підрядковий
збіг каналу ("Organic *" замість точного "Organic Search", §6.2.4 плану). Це внутрішня властивість
дизайну самого PDF-звіту Reporting Ninja — не щось, що продукт міг би виправити чи мав би
відтворити; навпаки, наш продукт свідомо повторює точнішу першу модель (first-user, точний збіг),
що й підтверджує §2 — обидва режими нашого тула дають 1,178, як і арбітр.

**Обидві розбіжності зводяться до одного й того самого факту:** коли хтось рахує "органічні
конверсії" за сесійною атрибуцією замість атрибуції за першим користувачем, число падає приблизно
на 5–7% — саме той діапазон, що вже фіксувався в проєкті раніше (§6.2.3 плану).

### Що НЕ є причиною (перевірено й відкинуто)

- **Різний період** (гіпотеза §6.2.1, найімовірніша за замовчуванням) — відкинуто: §1 вище доводить
  усі вісім джерел на одному періоді, і `client-report` дав ІДЕНТИЧНІ clicks/impressions
  (8,598/179,118) з рештою джерел — розходяться лише GA4-похідні числа, чого не було б при зсуві
  періоду (зсув зачепив би й GSC-числа теж).
- **Тип GSC property** (§6.2.2) — не застосовно, GSC-числа у всіх джерелах ідентичні.
- **Кеш RN** (§6.2.5) — не застосовно, PDF і API-джерела Reporting Ninja дають РІЗНІ числа
  одне з одним (1,178 у таблиці PDF vs 1,115 у `client-report`), а не однаково застарілі.
- **Часовий пояс** (§6.2.6) — малоймовірно: різниця в 4.66–6.54% значно перевищує типовий ефект
  зсуву межі місяця на день для клієнта з рівномірним трафіком; конкретний і відтворюваний механізм
  (атрибуція) пояснює обидва випадки без залучення часового поясу.
